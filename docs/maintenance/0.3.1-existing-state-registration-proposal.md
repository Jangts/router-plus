# Router Plus 0.3.1 提案：复用已有状态的公开注册入口

日期：2026-11-12。状态：原始提案已按实施方案落地；实际结果见[验证记录](0.3.1-existing-state-registration-acceptance-2026-11-12.md)。本文保留提案，不作为当前 API 参考。

评估与实施边界见 [0.3.1 落地方案](0.3.1-existing-state-registration-implementation-plan.md)。本文保留原始提案；执行顺序、能力收敛及验收以落地方案为准。

## 目标与范围

把 Vue、React hooks 和 Zustand／Redux／Jotai 适配器内部的来源注册逻辑抽出为公开入口。已有状态可直接接入；现有创建型 API 创建原生来源后，调用同一注册入口，再返回原生结果。Router Plus 只保存访问索引、初值及必要快照，不创建第二份实时状态，也不要求业务维护额外注册表、请求 Store 或 watch/consume 消息桥。

本提案不升级包版本、不发布、不修改业务消费者。权限、字段校验、草稿冲突、保存确认与业务副作用仍由原状态来源的 setter／action 拥有。

## Vue：useVueState

建议从 `@jangts/router-plus/vue` 导出：

```ts
useVueState(source, idOrOptions): void
```

接收已有 ref（含 computed）、reactive 对象或 `{ get, set? }` 访问器；通过重载保留值类型，按 `isRef → isReactive → 访问器` 的顺序识别。访问器需检查 get／set 的可调用性；先识别原生来源，避免业务对象上的同名字段被误判。

只负责注册、订阅、作用域与清理，不创建 ref、reactive 或 computed，不转换来源，不返回替代状态。只读 ref／computed 和只有 get 的访问器拒绝外部写入。普通值及无访问器语义的普通对象拒绝注册。

```ts
const draft = reactive({ name: '' })
useVueState(draft, 'campaign/draft')
useVueState({ get: () => store.name, set: value => store.setName(value) }, 'campaign/name')
```

`useRpRef`、`useRpReactiveState`、`useRpComputedState` 保留现有创建参数、返回类型及原生对象身份，内部统一为“原生创建 → useVueState → 返回原生结果”。未提供登记参数时跳过注册，不要求 Provider。组件来源按页面实例隔离；setup Store 来源按一个 Router Plus 实例管理，随其 effect scope 清理。

## React：useReactState

建议从 `@jangts/router-plus/react` 导出只注册的 Hook：

```tsx
const state = useState(initial)
const input = useRef<HTMLInputElement | null>(null)
const submit = useCallback(handleSubmit, dependencies)

useReactState(state, 'form')
useReactState(input, 'input')
useReactState(submit, 'submit')
useReactState({ get: () => value, set: next => update(next) }, 'draft')
useReactState({ get: () => summary }, 'summary')
```

返回 `void`；支持 `[value, setter]`、ref、可调用函数及 `{ get, set? }`。普通值以 `{ get }` 显式接入，避免数组值与 state 元组混淆；函数直接传入表示可调用来源，函数值本身的只读访问使用 `{ get }`。识别元组时必须检查长度与 setter 可调用性。该约定属于注册输入语义，不支持从任意普通值自动猜测来源。

抽取现有 `useBinding` 的生命周期实现，保留最新闭包访问、首次初值、页面 scope 与卸载清理。注册在 effect 提交阶段进行，废弃 render 不产生登记；Strict Mode 的 setup/cleanup/setup 不遗留重复 ID、订阅或来源。普通重渲染不反复登记；ID、所有者或读写能力变化时正确重建，不能保留旧闭包。登记配置在一次登记生命周期内固定。

已有便捷 API 无条件调用该 Hook，不能按 options 是否存在条件调用 Hook：

- `useRpState`：原生 useState → useReactState(tuple, options) → 返回 tuple。
- `useRpRef`：原生 useRef → 注册 → 返回原 ref。
- `useRpCallback`：原生 useCallback → 注册可调用来源 → 返回 callback。
- `useRpContext`：原生 useContext → 用只读 get 注册结果 → 返回 context 值。

不传登记参数时内部跳过注册，不要求 Provider。React ref 没有原生变更订阅：直接 `.current` 读取保持最新，但直接写入不保证即时通知；沿用已有可观察性边界，不轮询，不伪造响应式保证。state setter 必须使用函数包装写入函数类型值，避免被 React 当成 updater 执行。

## Store：独立注册函数

建议在对应 `@jangts/router-plus/stores/*` 子路径导出以下普通函数；不是 React Hook，不要求组件挂载。

```ts
registerZustandState(plus, store, idOrOptions): () => void
registerReduxState(plus, store, idOrOptions): () => void
registerJotaiState(plus, store, atom, idOrOptions): () => void
```

名称为本提案建议名，实施前核对与 useVueState／useReactState 的同组命名一致性。参数顺序固定依赖在前，原生来源次之，登记配置在后。

所有入口直接使用已有 Store，不创建 Store、不替换原生方法、不改变对象身份；复用同一 Core binding host。返回幂等注销函数，聚合清理主来源、动作子来源与订阅；Router Plus dispose 也负责兜底清理。共享 Store 不随任意组件卸载注销，SSR 每个请求使用独立 Router Plus 和 Store。重复活跃 ID 报错，不静默覆盖；批量登记中途失败须回滚已登记部分。

### Zustand

复用 `getState/setState/subscribe`，兼容 bound store 与 vanilla StoreApi，并保留 middleware 的原生类型。状态数据和动作分开索引，动作使用 `ID/method`，调用时读取最新方法并保留 receiver。

外部状态写入采用原生 merge 语义，不能因替换快照丢失动作。已有 `createRpZustand` 创建完 Store 后调用 registerZustandState，再返回原结果，不保留第二份注册实现。动态新增／移除动作的支持范围必须明确，不能承诺仅首次枚举无法实现的动态行为。

### Redux

复用 `getState/subscribe/dispatch`，在 `ID/dispatch` 暴露原生 dispatch 调用。已有 Store 默认只读状态并允许显式调用 dispatch；Redux 没有通用 setState，不能向任意 reducer dispatch 一个虚构更新 action 并声称已经写入成功。

需要 `setState` 时，登记配置提供类型化 `set(next)` 适配，内部 dispatch 业务已有 action；其状态类型从 store.getState 推导。没有写适配的 Store 不可绑定需要恢复写入的 QS。该 set 配置属于 Store 注册适配，不混进通用字段导航规则。

现有 configureRpReduxStore 的 reducer 更新包装属于创建阶段能力：如保留，则由创建包装器准备 reducer 与对应写适配，创建后统一调用 registerReduxState。已有 Store 注册不调用 replaceReducer，不假定能取回或包裹既有 reducer。读取、订阅、dispatch 和写适配的登记只有一份实现。

### Jotai

显式接收既有 Store 与 atom，复用 `get/set/sub`，不默认使用另一份全局 Store。只读 atom 只读；可写 atom 的 callState 按原始参数元组调用 store.set，并保留返回类型。

“可写 atom”不等于“可通过一个新值赋值”：派生 atom 可能接收命令或多个参数。不得仅因存在 write 字段就对任意 WritableAtom 开放 setState(value)。建议默认登记读取及原生调用；赋值式 setState 需要显式 set(next) 适配，或由创建入口在明确 primitive atom 的创建分支提供该适配。不要依赖 Jotai 私有标记猜测任意已有 atom 的赋值语义。

createRpJotaiAtom 创建 atom 后调用同一公开注册函数，保持 atom 身份、原生重载和 Store 归属。

## 内部结构与兼容要求

1. Core bindNativeSource／binding host 继续作为统一底层；来源识别与生命周期由框架适配器负责，不把框架类型判断搬入 Core。
2. Vue 抽出公开 useVueState；React 抽出公开 useReactState；三个 Store 分别抽出公开注册函数。便捷创建 API 必须实际委托公开注册入口。
3. 保留现有 getState／setState／callState／scope、QS 编解码、校验、只读限制和来源冲突语义，不另建注册总线。callState 的动作结果与命令结果封装保持现有合同。
4. 新入口及便捷入口对同一能力使用相同桥接和错误语义；创建阶段才有的能力通过显式适配传入，不伪装成已有来源的通用能力。
5. 类型签名保留值、setter、action 参数、返回值和原生 Store 类型；不以对外 any 重载代替推导。公开入口是追加能力，既有创建 API 不因抽取改变正常行为。

## 实施验收范围

以下为后续实现的验收要求，不表示本提案已运行或通过测试。

- 直接注册与创建包装入口读写同一原生来源；双向修改不产生第二份实时状态。
- Vue 原始 ref／reactive 身份、只读约束、访问器 setter、组件及 Store scope 清理正确。
- React 最新闭包、函数类型 state、页面实例切换、Strict Mode、卸载和未传 options 正确；不在 render 期间产生注册副作用。
- Store 注销聚合动作与订阅；重复 ID 和局部登记失败无泄漏；组件卸载不误注销共享 Store，SSR 无跨请求共享。
- Zustand 保留动作和原生 merge；Redux 不改既有 reducer，未配置写适配时拒绝赋值；Jotai 只读／赋值／多参数命令写入分别验证。
- 对 React tuple／ref／callback／访问器与三个 Store 编写最小类型用例，覆盖只读及错误参数拒绝。
- 更新 exports、API 文档、框架示例与状态绑定说明时区分已实现能力和提案；本提案阶段不把新入口写入现行 README 或发布日志。
