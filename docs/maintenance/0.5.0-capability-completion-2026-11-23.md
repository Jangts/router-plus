# Router Plus 0.5 能力补全与交叉验收

本轮按使用路径审查能力完整性，三个子任务分别负责 Core、框架适配和文档／实际包体消费，并交叉检查彼此产物。关联[迭代计划](0.5.0-iteration-plan.md)与[实施验收](0.5.0-implementation-acceptance-2026-11-23.md)。

| 原有接入负担 | 完善后的入口 | 验证位置 |
| --- | --- | --- |
| 每页复制 query 的合并、删除、数组处理与无变化判断 | Core／scope／global 的 patchQuery、execute query.patch、React setter.patch、Vue patchQuery；共用短期协调器 | capability-core-050、framework-capabilities-050、live-contracts-050 |
| 原生函数式 query 输入需再包 createSearchParams | 函数可返回完整 PageQueryInit，保留原有完整替换语义 | Core 与框架 query 回归、打包类型消费 |
| 已有目录变动需额外 ready 常真占位 | 原生绑定直接观察 validate 与 codec 的依赖 | live-contracts-050 |
| 目录位于独立 Store／Atom 时应用手动重新登记 | observe 订阅规则依赖，绑定拥有安装和清理；ready 保持纯读取 | 独立 Zustand 目录恢复、同步通知、错误清理和打包运行消费 |
| page+params 深链仍需拼锚点字符串 | 页 ID 目标支持 hash，并经过目标校验 | page hash 运行及类型消费 |
| Vue 自定义外壳需自己持有访问缓存 | View／Retained 接收 host，库保留实例、冻结和释放职责 | Vue 自定义宿主 DOM 保留与释放回归 |
| 链接整页导航、禁用与属性透传需业务包装 | 两端 Link 提供 reloadDocument、完整 disabled 和 DOM／辅助属性透传 | React／Vue 链接回归 |
| 能力清单不能代替完整接线 | 双语应用集成指南：原生状态、业务请求单一触发／取消、守卫模式、保留视图及职责裁切 | 指南独立代码块从实际 tarball 严格编译 |

## 收敛边界

业务枚举、权限、目录加载／空目录含义、版本 ID 映射、业务请求与取消、未保存内容确认、站内协议、旧历史迁移、布局和滚动仍由应用持有。没有引入另一份持续 query 状态、轮询或业务 DSL。

同页跨 facade 的 query 更新共用协调器；释放的 facade 只取消其编辑，不取消仍有效调用者；冻结的页面不会因过期编辑跳回。纯 patch 不将读取默认值写入 URL。具体检查结果及最终包指纹统一记入实施验收，避免中间产物冒充最终包。

消费者源码保持原状，本轮不包含 npm 发布、部署或真实浏览器视觉验收。Data Router 专属配方遵守原生框架的能力前提，声明式路由的最低版本支持单独验证。

## 最终验证

267 项回归全部通过。原生状态与 query 修改统一进入短期地址事务，覆盖同轮两种顺序和慢守卫；跨 facade 编辑共用协调、外部导航取消过期意图，原生重定向和现代 blocker 保持。当前／最低依赖消费使用同一最终包，8／7 个配方严格检查（最低组合按已声明能力前提排除 Data Router 配方），双语文档生成及工作区差异检查通过。日志和最终指纹见实施验收记录。
