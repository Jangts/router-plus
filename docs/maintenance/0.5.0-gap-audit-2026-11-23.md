# Router Plus 0.5.0 补充遗漏审计

日期：2026-11-23。范围：0.5 库实现、公开类型、导航与原生状态调用链、保留视图、打包消费和相邻文档站。检查依据为迭代计划 P01—P06、D01—D03，主要覆盖接口一致性、实例隔离、并发、恢复、清理和交付。最终验证与边界见[实施验收记录](0.5.0-implementation-acceptance-2026-11-23.md)。

## 已修复项

| 编号 | 触发条件与影响 | 完善后的行为及证据 |
| --- | --- | --- |
| A01 | 分组 query: true 的字段只补校验、codec 或省略配置；登记快照中的 undefined 意外盖掉继承 query | 合并字段规则时忽略 undefined，保留显式 false；分组字段回归覆盖初读与回写 |
| A02 | 根 omitDefault: true，字段显式 false；整体提前省略覆盖字段选择 | 展开分组逐字段决定省略，显式保留默认参数的用例通过 |
| A03 | 原生来源被赋予非法枚举；只输出诊断，控件仍显示非法选择 | 恢复已提交地址对应值，保留原始地址与诊断 |
| A04 | 加载期间只修改未绑定的对象字段；被误判成用户改变地址意图 | 使用临时待就绪基线比较归属 query 投影；本地字段与待恢复 URL 同时保留 |
| A05 | 同一路由的多个参数实例保留；页面级登记元数据携带最近实例回调 | 上下文构造、目标解析、原生通知、命令与历史读取实际实例的已登记规则；原始静态声明独立保存，默认与合法值不会借用其他实例 |
| A06 | 异步 codec 目录更新，但新旧值均合法 | 除合法性外观察来源的地址投影变化，重新恢复当前地址映射；React valid-to-valid 目录回归通过 |
| A07 | 提交 query 后，在微任务执行前修改原 URLSearchParams、数组／对象输入或选项容器 | 提交时捕获参数及选项容器；回调执行仍基于提交基线 |
| A08 | 第一次 query 导航等待守卫，下一轮又执行函数式修改 | 后续修改接续尚未提交的提案；外部已提交导航重置基线，已结束提案释放；慢守卫用例无丢参 |
| A09 | query 回调抛错或误返回 Promise | 统一返回 failed 回执，保留地址；异步输入不会被当成空参数对象，拒绝的 Promise 也有清理 |
| A10 | ready 绑定的原生取消订阅抛错 | 继续清理其他原生订阅、地址监听、动态规则及索引；释放故障诊断后，聚合清理与 dispose 仍可完成 |
| A11 | 默认值与当前值是不同 Map／Set；JSON.stringify 都得到空对象 | 结构比较覆盖 Date、Map、Set、数组及普通对象，避免默认省略误吞更改；不再将类实例统一当空对象 |
| A12 | Vue 保留页进入空／未匹配 outlet | 保留隐藏子树，返回时继续使用同一 DOM；显式 release 仍重建 |
| A13 | 全局 query 来源处于未登记页面路径 | 全局规则参与解析与恢复，可读写且保留其他 query/hash；不要求伪造页面实例 |
| A14 | 原生初始地址携带 framework matched 映射，随后合成另一个目标 | 合成目标不复制来源的页面匹配权威；目标守卫使用实际目标页面上下文 |
| A15 | codec 返回 any，参与反向泛型推断；最低 peer 消费时原生值被拓宽 | 原生初值／来源决定类型，选项通过 NoInfer 使用该类型；打包声明包含 Date／Map／对象 decoder 的实际消费检查 |

## 第二轮交叉检查

第二轮重点反向检查局部更新、全局异步恢复、scoped 接口与 React 登记生命周期。以下 10 类问题分别有失败复现和修复后回归，新增 12 项测试；主要证据为 test/query-races-050.test.mjs 和 React 新登记 ID 用例。

| 编号 | 问题与影响 | 修复与验收 |
| --- | --- | --- |
| B01 | 同轮 page query patch 都读取旧原生值，后一修改吞掉前一修改 | 根实例及 scoped patch 读取同一待提交投影，顺序合并局部字段 |
| B02 | Store 字段更新及非 query 异步 setter 在写入前读取旧 root | 全局来源按自己的队列读取、修改和写入；query 字段写入复用待提交投影，连续字段写入与异步局部更新均保留 |
| B03 | resetState 对 Store 字段路径返回 unknown | 沿已登记 root 的默认值解析字段，只恢复目标字段，保留其他字段 |
| B04 | 未登记页面上的全局恢复失败只产生日志，导航仍报告成功 | 实际已提交导航返回 failed，并保留 committed: true |
| B05 | 全局旧慢恢复与新恢复并行，旧请求最后写回 | 原生写入与地址恢复共用来源队列，执行前核对来源及活动地址；旧错误不污染新地址。保留策略重新生成 context 时仍恢复 |
| B06 | React 更换 ID／实例时沿用旧 initial、回调单元与通知集合 | 捕获单元、默认值、回调配置与监听集合跟随提交后的登记身份；新 ID 捕获自己的当前原生值 |
| B07 | scope.whenReady 漏等全局地址恢复 | 与根入口一样等待当前全局恢复任务，不把来源尚未恢复当作已就绪 |
| B08 | 失败的全局来源注销后，缓存错误仍让后续未登记路径导航失败 | 下一次地址应用清理过期恢复错误，后续导航回执反映当前来源状态 |
| B09 | 旧 patch 等守卫时发生外部导航，下一次局部更新仍借用旧提案 | 待提交项携带地址基线；读取和合并时核对路径、实例与 entryKey，外部导航后的更新基于新地址 |
| B10 | 页面旧慢恢复未结束，新地址恰好等于当时原生值；提前相等判断跳过新恢复，旧写入随后覆盖它 | 把相等与地址有效性判断放入来源队列，过期排队恢复退出；新的地址自动恢复，无需额外调用 whenReady 掩盖错误 |

原始复现输出保存于 .tmp/050-second-before.log、050-second-scoped-before.log、050-second-external-before.log 与 050-second-page-before.log；最终结果见实施验收记录的第二轮日志。这里的完成结论限于库和包体验证，未扩展为消费者上线结论。

## 核实后沿用的合同

- 根对象来源（含 Date、Map、Set）的 decoder 接收仅含归属参数的 URLSearchParams；字段 decoder 接收字符串。原有兼容回归继续保留，没有改动这一输入合同。
- 公开 Core 的 setState/setTab 已返回真实回执；未导出的旧兼容 hook 不作为新增公开入口。
- 原生状态在慢守卫期间连续变化的既有协调用例通过，继续复用现有队列。
- 业务合法值、权限、加载失败与空目录的含义、已知页面白名单、表单确认和应用数据加载由消费者拥有。
