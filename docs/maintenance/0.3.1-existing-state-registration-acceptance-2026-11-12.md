# Router Plus 0.3.1 已有来源登记实现与验证记录

日期：2026-11-12。范围为[实施方案](0.3.1-existing-state-registration-implementation-plan.md)的 S1—S6。目标功能已实现，包版本仍为 0.3.0；本记录不是 npm 发布或线上验收记录。

## 实现结果

| 范围 | 实际实现 |
| --- | --- |
| Vue | 公开 `useVueState`；ref/computed、reactive/readonly 容器与访问器共用适配清单。创建 composables 委托同一入口，effect scope 自动清理。 |
| React | 公开 `useReactState`；tuple、ref、callback、访问器共用适配清单。创建 hooks 委托同一入口；仅 commit 更新可见来源，effect 登记／清理。 |
| Zustand | 公开 `registerZustandState`，原生 merge 保留动作；固定登记时动作名称，同名动作取最新方法与 receiver。 |
| Redux | 公开 `registerReduxState` 与 `ReduxStateOptions`；已有 Store 默认只读，原生 dispatch 独立索引，显式 set 开放赋值／QS；仅创建阶段准备生成 writer。 |
| Jotai | 公开 `registerJotaiState` 与 `JotaiStateOptions`；原生命令与完整值赋值分离。已有 writable atom 需显式 setter 才能赋值，创建器仅为确定的默认 primitive 构造准备赋值适配。 |
| Core | 沿用 binding host，增加单来源／登记组回滚、延迟观察、幂等聚合清理与 dispose 兜底。订阅初始化通知不覆盖地址恢复；注销使等待中的调用／写入回执失效，保留真实导航提交事实。 |
| 文档 | README、状态合同、框架说明、中英文指南及 API 编排源稿同步；API 页面从源码重新生成。修正使用入口中残留的已退役 Store 子路径。 |

没有增加实时状态副本、第二套登记总线或通用业务 Store。通用 `registerStateBridge` 仍是内部适配机制。未修改 Cafe 或其他业务消费者。

新增行为回归位于 `test/existing-frameworks.test.mjs` 与 `test/existing-stores.test.mjs`：

- React Strict Mode 自动清理、函数 state、ref、getter-only、ID／能力切换；Suspense 废弃 render 不发布候选 callback／getter。
- Vue 已有 ref、readonly 容器、Map 同对象写入、含业务 get 字段的 reactive 对象、访问器 receiver 与响应式读取；既有回归同时覆盖 Array／Set、computed、Pinia scope 和 QS 归属释放。
- Zustand merge、动作同名替换／移除／新增、动作冲突后的整组回滚；订阅同步抛错与即时通知不留下索引／元数据；清理异常、重复 stop、dispose 兜底及诊断出口异常。
- Redux 默认只读、dispatch、显式业务 setter、只读 QS 拒绝及创建器业务 setter 优先；Jotai 多参数／异步命令、已有 primitive 的显式赋值、创建 primitive 的默认赋值、不同 Store 隔离、dispose 后拒绝登记。
- Jotai onMount 初始化变更与 QS 恢复的先后顺序；注销期间等待中的写入／调用失效，QS 写入保留 `committed: true`。

Redux 登记配置使用 `NoInfer` 以来源值类型为准；消费者反例明确标注原生 reducer 的 state，避免原生 `any` 推断使错误配置检查失效。React 首次通知不得把恢复前值写回 QS；该时序有通过的回归覆盖。

## 验证边界

验证使用本地离线测试、JSDOM、内存路由及原生 Store，不包含真实浏览器视觉、Cafe 运行或生产验证。未启动应用、截图、压测、发布 npm 或部署文档站。包版本与文档站依赖维持 0.3.0，0.3.1 作为目标功能名称；变更暂记入 Unreleased。

原生 setter／dispatch／atom 生命周期已经发出的业务副作用不保证可逆；注销取消的是来源可见性和操作回执。应用继续拥有业务校验、权限与副作用语义。
