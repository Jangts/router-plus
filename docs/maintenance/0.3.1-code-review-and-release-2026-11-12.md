## 发现及修复复查

| 编号 | 触发与影响 | 修复及回归证据 |
| --- | --- | --- |
| R01 | 页面来源注销后异步 setter 拒绝，原回执被当成仍有效的业务失败。 | 按来源身份返回 cancelled，且不覆盖替换来源；`existing-stores.test.mjs`。 |
| R02 | `pages: []` 时，全局来源间的相同 QS 参数没有静态页面表帮助检查。 | 直接检查全局来源参数归属，失败不登记第二来源；`existing-stores.test.mjs`。 |
| R03 | 等待中的 QS 恢复失败晚于注销，可能污染替换来源的恢复错误记录。 | 全局／页面恢复均核对来源身份；原来源晚到错误不发布、不污染下一次导航；`existing-stores.test.mjs`。 |
| R04 | `scope.getState/setState/patchState` 对 `store/field` 路径与根实例行为不一致，全局 ID 未进入 scoped key 列表。 | 门面委托同一全局路径实现，包含全局登记 ID；`release-review.test.mjs`。 |
| R05 | 已结束的 scope 调用命令可能同步抛错；已 dispose 的 Core 可被直接交互方法重新创建高亮／导览。 | 作用域命令与直接交互统一检查存活与就绪状态，返回取消回执；`release-review.test.mjs`。 |
| R06 | 异步目标查找、scroll strategy 或 afterStep 在取消后才完成／抛错，可能返回 target-not-found、failed 或成功。 | 结算前统一检查捕获的 signal／tour token，保持 cancelled；`release-review.test.mjs`。 |
| R07 | DOM runtime 的同一注销句柄重复调用，会扣除其他活跃使用者的引用。 | 每个句柄只释放一次，并检查所属安装记录，旧句柄不能注销新安装；`dom-runtime.test.mjs`。 |
| R08 | renderer.mount 分配资源后抛错，原回滚只销毁成功完成 mount 的 renderer。 | 在调用 mount 前建立清理所有权，部分挂载也执行 destroy；`release-review.test.mjs`。 |
| R09 | `constructor`／`__proto__` 等查询键因原型继承判断被遗漏。 | 用 own-property 判断及数据属性写入，保留首个值且不改变对象原型；`release-review.test.mjs`。 |
| R10 | React 链接的空字符串 download 属性被当成普通站内跳转拦截。 | 明确识别 download 属性存在，保留浏览器下载；`existing-frameworks.test.mjs`。 |

修复均有通过的行为回归；本次检查范围内未留下已确认的发布阻断问题。源码审阅和回归并不构成所有输入、所有 peer 版本及所有宿主环境的穷举证明。
