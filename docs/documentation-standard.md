# 文档规范

本规范适用于全仓库的 README、设计说明、API 参考、使用指南、操作手册、Skill、示例说明及由这些内容生成的网站。各应用、公共包和部署设施均遵守同一内容原则。

## 正式文档

正式文档描述最新、最终确定的产品、设计、接口与操作方式。读者无需参与项目讨论、理解开发进度或查阅旧方案，就能据此学习和使用。

- 直接解释是什么、如何使用、输入输出、默认值、策略、边界、错误及职责；示例与公开接口保持一致。
- 按成品组织已确定的设计，不使用“即将支持”“本轮完成”“尚待接入”等项目进度措辞。确定的合同与实现有差异时，在独立计划或问题记录中跟踪并修正实现，不把差异说明塞入使用文档，也不虚构运行结果。
- 不叙述之前的写法、迁移经过、版本对照、实现成果、验收数量、授权过程或对话中的思路。必要的设计依据写成自足的技术理由，不引用“用户说过”“我们讨论”“按你的要求”等沟通背景。
- 明确当前适用范围及真实限制。运行时的历史查询、业务待办、错误恢复、数据迁移和备份操作属于产品或运维功能，应保留其准确说明；它们不是项目进度记录。
- 面向 SDK 使用者的页面不介绍文档站自身的托管、构建、生成过程或发布进度。站点维护、构建与部署说明单独服务于站点维护者。
- 不把未决定的选择写成产品能力；未决定事项进入讨论纪要或计划。正式文档不设置“待确认”“待处理”“开放问题”段落。

## 过程资料

修改日志、讨论纪要、计划、调查和验收记录使用独立文档，标题及索引清楚标明用途，与正式参考分组呈现。修改日志记录变更，纪要记录问题、结论与依据，计划记录目标、范围、依赖与待办；这些内容不构成另一套正式接口文档。

长期维护所需的过程资料放在所属应用或包的维护文档目录。一次性审计、调试输出及临时报告按仓库输出目录约定保存；用户原件和业务资料保持原有用途，不按技术文档清理。移动已有记录时保留有效链接、必要证据与明确约束，不通过删除证据伪装任务完成。

正式文档可以提供独立维护资料的入口，但不在正文中复述项目时间线、阶段状态或待办。面向使用者的 API 和教程导航不混入内部计划及交接记录。

## 同步与审校

修改接口、配置、默认值、策略或行为时，同步责任文档、示例、Skill 和文档站源稿。生成内容修改其来源并重新生成，不只修补产物。

审校按语义判断，不能批量删除“历史”“计划”“后续”等词：它们也可能描述合法的产品概念。检查重点是内容是否服务当前读者，是否准确陈述确定的合同，是否混入沟通或实施过程，是否有重复且相互冲突的参考。

文档检查依据本次变动选择最小有效范围，包括链接、公开签名、示例和生成一致性。验证结果记录在专门维护记录或交付说明，不写进正式使用正文；没有执行的检查不得声称通过。

## 公开包的使用入口与发布检查

公开 npm 包的 README 服务首次接触该包的使用者，必须让读者能够判断适用场景并完成第一次实际使用。已经具备有效引导的文档保持原有结构，只修正明确缺口；不得为了统一版式、字数或目录而重写。现有双语 README 保持英文在前、中文在后及语言切换锚点，内容修改不擅自改变语言顺序。

发布前从使用者视角核对以下内容，而不是仅检查文档是否存在：

- 定位与前提：说明解决什么问题、适合什么任务、需要什么运行环境，以及必需依赖、peer 依赖或外部服务。包说明与实际公开能力一致。
- 首次使用：提供真实安装命令、完整公开 import、最小有效代码、文件或接入位置、运行方式及预期结果。应用集成库说明宿主接线位置；有凭据、服务端身份或浏览器环境要求时明确来源，不用未说明的变量冒充完整示例。
- 继续使用：按常见任务给出足够的调用示例与详细文档入口，交代参数、结果读取、默认值和必要错误／生命周期语义。介绍机制和罗列链接不能代替使用引导，README 也不需要复制整份 API 参考。
- 链接与交付：核对源码、发布白名单及实际 tarball。相对链接的目标必须随包交付或由明确的公开仓库承载；站点链接指向实际对应页面。内部构建、部署和审计流程不作为消费者上手步骤，维护资料保留在自己的入口。
- 搜索元数据：核对 package.json 的 description 与 keywords 是否准确覆盖包的主要任务、关键协议、框架／运行环境及有辨识度的能力。关键词以 npm 使用者会搜索的英文术语为主，不按数量凑词，不堆泛词、重复词或尚未实现的能力；已经合适的词保持不动。

有改动的示例按具体疑问做最小验证，区分严格类型检查、离线执行、模拟服务及真实外部服务；未经验证不宣称已运行。文档或元数据修订不自动触发完整构建、测试、应用启动或发布，继续遵守运行频率及授权边界。

发布操作必须核对最终包体中的 README 和元数据；npm 返回成功后，再读取公共 registry，确认版本、标签、完整性、README 内容与关键词和预期一致。仓库文件检查不能代替最终包体检查，提交成功不能代替公共可用性核对。检查结论及实际未验证项留在发布记录中，不写入正式 README。
