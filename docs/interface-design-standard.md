# 接口设计规范

本规范适用于本项目的应用、公共包、工具与配置接口。接口服务于学习、阅读与正确使用；使用者掌握基础调用后，应能按同一规律理解其他入口，并在原有写法上逐步增加能力。具体运行合同以对应模块的 API 文档为准。

## 简化的三个来源

| 方式 | 设计要求 | 典型用途 |
| --- | --- | --- |
| 缺省 | 内置或提前配置确定的值可以省略，含义明确且可预测 | 常用策略、可选字段、固定依赖 |
| 复用 | 已有定义和实例可以直接组合或派生，不复制同一决定 | 基础 Workflow、模型配置、工具清单、具名 handler |
| 代指 | 通过稳定标识引用已绑定实体；有关联关系的字段由拥有该关系的一方生成 | 模型选择、工具调用、资料引用、路由标识 |

简化衡量的是需要理解的概念、需要作出的决定和需要追踪的关系。行数和字符数只是辅助证据。删除 await、增加一层函数或把一个函数改成三个配置字段，不能单独证明设计更简单。

新增封装必须说明它替使用者省去了什么决定、重复配置或通用判断。如果只是原样接收所有字段，再换一个对象返回，应优先直接使用原接口。

## 同一入口逐步扩展

最小用法是完整用法的子集。增加能力时继续使用同一构造、执行和结果读取方式，按需补充配置、登记或实现；不要求使用者切换到另一套 DSL 或平行执行框架。简化来自减少决定和重复关系，不能靠隐藏授权、取消、完整结果或真实副作用制造简单。

## 实例拥有固定关系

稳定配置、默认依赖及一对一关系由实例绑定，集合通过登记管理。身份、取消信号、请求状态、预算和当前权限按真实生命周期传入，不能固化进跨请求共享定义。

绑定、派生和组合明确身份与可变性：是否允许重复绑定，选择是否仅影响本次请求，派生是否共享状态或额度，组合如何处理冲突，均写入所属合同。普通对象与带原型方法的实例遵守同一接口；保留方法接收者、私有状态及合同允许的 getter。配置快照不整体复制或冻结应用服务。

## 一致性先于局部省写

同一概念统一名称、字段结构和语义；同组方法保持相同参数顺序、可选项位置和输入输出关系。

- 目标、来源、比较路径与比较值按各自语义命名，同组方法保持参数方向一致。
- 字段路径按同一规则解释，包括数组下标；不在不同入口切换路径语法。
- 真值判断、已定义、非空、相等、错误存在和可交付分别表达，不用模糊的“有值”覆盖所有语义。
- 执行身份、定义身份、实体引用、序号、数量、绝对时间及持续时间不能混用；单位和作用域明确标注。
- 同步接口拒绝异步结果；异步接口等待真实完成。抛错、错误返回值和布尔值按合同区分。
- 默认值说明含义、优先级、作用域及覆盖方式。0、空字符串、undefined、空集合、未处理与失败分别解释。

名称、默认值与参数顺序结合整组接口评审，类型与运行时校验共同保证合同。

## 原始合同与生成方式

原始配置可以是规范、完整的用法。便捷函数固化常用选择逻辑、推荐策略或可推导关系，生成同一种原始合同。参数套壳、同义别名、字符数与代码行数减少均不能单独证明接口更简单。

专用生成器拥有自己的默认命名及补全规则，通用层校验手写配置与生成产物。通用执行层不猜测配置来自哪个 helper，不通过额外标记为特定 helper 开另一条路径。

可推导标识由生成器负责；需要稳定关联时不使用随机身份。重复标识、冲突、继承和覆盖分别由所属合同规定。仅在存在外部关联或明确可读性需要时要求调用者重复提供标识。

## 基础能力、接入支持与可选扩展

核心接口定义调用与回调的合同及通用保证。推荐实现、便利构造和场景策略遵循同一合同；可选扩展拥有自身的局部协议、状态与生命周期，不把扩展业务概念升级为所有使用者的必填字段。

基础缺省根据缺参时能否合理执行确定；场景补全根据已有信息和明确策略生成。推荐值可以是标量、对象或 handler；保留自定义实现与精确覆盖。档位须说明映射、成本及适用条件，没有模型、环境或业务依据时不承诺质量、速度和容量。

按实际职责组织接口、Adapter、Hook、回调、注册表及组件组合。复用现有框架的扩展机制，不为分类完整另造执行框架或要求每个 API 只能属于一个类别。

## 观察、日志和真实副作用

执行者提供真实执行身份、开始结束、错误、取消及提交事实。观察、预览和日志投影关联实际执行，不能冒充额外调用、最终验证或授权。宿主拥有诊断存储、保留期与披露范围，库不假设宿主的数据表或持久化方式。

取消等待、超时、停止本地界面与实际副作用终止分别保证。保留已经发生的提交及真实回执；重试安全性由幂等或对账合同决定。观察失败不掩盖业务错误，执行必需校验不能降为尽力记录。

## 公开面、示例与评审

每个公开入口有明确职责，聚合入口和子入口转出同一实现。动态输入保持 unknown 并在边界解析；公开类型、返回收窄与实际保存的投影一致。便利输入返回同一种结果合同，合法 undefined、未处理、失败及完成按合同区分。

公开能力、字段及场景具有本项目内可用的文档入口。示例通过公开接口消费，同一业务由简入繁，交代输入、返回、运行前提和预期结果。策略实现可查；正式文档与过程资料遵守[文档规范](documentation-standard.md)分别维护。

评审主要接口时逐项回答：

1. 固定配置或可推导关系是否仍在反复传递？
2. 从最小用法增加需求，是否沿用同一入口？
3. 同组命名、参数方向、字段、单位和返回是否一致？
4. 封装是否固化了真实逻辑与策略？
5. 专用规则是否错误地进入公共层？
6. 对象、实例、getter 与接收者是否按同一合同工作？
7. 自定义实现是否保留取消、授权、预算、完整结果和副作用边界？
8. 文档、示例、声明、生成来源及真实消费者是否一致？
